# O8.2 staff commands and Staff & Access

Status: **PASSED WITH LIMITATIONS**.

Staff & Access calls the register commands. Those commands call `staff.rs`. A cashier session is refused in `staff_actor` unless the role is Store Manager or Super Admin and the permission `users:create` is present.

## Commands

| Command | Library |
| --- | --- |
| `list_register_staff` | reads `cached_users` |
| `create_register_staff` | `create_local` |
| `edit_register_staff` | `edit_local` |
| `reset_register_staff_pin` | `reset_pin_local` |
| `disable_register_staff` | `disable_local` |
| `register_staff_seats` | signed entitlement `limits.staff` |
| `submit_staff_provisioning` | posts pending rows to `POST /api/v1/users/provision`, then imports `GET /api/v1/users/staff-feed` |

The panel is `StaffAccessPanel.tsx`. Create, edit, PIN reset, and disable each try the submit command. A missing user token leaves the local row pending. The financial `sync_queue` is not used.

`submit_staff_provisioning` sends the stored verifier, never the PIN. `accepted` and `duplicate` mark the event accepted. `provisioning_conflict` marks the event and does not change the local user. `403`, other `409`, and `422` mark the event rejected. A transport failure marks it `retryable`.

`unlock_by_id` still tries the server first. A 401 falls through to the local Argon2 check only when that user is `pending` on this register. A 403 or 423 stays a refusal. An unreachable server still uses the local cache.

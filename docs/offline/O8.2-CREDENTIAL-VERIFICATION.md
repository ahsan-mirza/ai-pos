# O8.2 credential verification

Status: **PASSED WITH LIMITATIONS**.

`POST /api/v1/auth/login-pin` and `POST /api/v1/auth/unlock` still call `rbac_service.authenticate`. No login route was added.

`security.verify_pin` now branches on the stored string:

- `scrypt$...` uses the existing pepper and `verify_password`. A missing hash still runs the dummy scrypt comparison.
- `$argon2id$...` uses `argon2.PasswordHasher.verify`. A mismatch or a malformed string returns false.
- Any other `$` prefix, including `$argon2i$`, returns false.
- A plaintext string fails the scrypt check.

Argon2 verifiers are not rewritten to scrypt. `UserOut` still exposes `has_pin` and not the hash. The staff feed still returns `pin_verifier` only to the device principal.

## Evidence

`tests/test_security.py` `test_pin_accepts_scrypt_and_argon2id_and_rejects_the_rest` covers a correct and incorrect scrypt PIN, an empty PIN, a malformed scrypt string, a correct and incorrect Argon2id PIN, a malformed Argon2id string, an `$argon2i$` prefix, and plaintext.

`tests/test_staff_provision.py` covers online login of an Argon2 verifier and the absence of that verifier from the user list.

Those tests are in the 20 pytest results. Lockout and `pos:access` were not redesigned. The five-attempt local lockout remains in the desktop suite.

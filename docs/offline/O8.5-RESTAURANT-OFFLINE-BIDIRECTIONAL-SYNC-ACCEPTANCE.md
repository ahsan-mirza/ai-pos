# O8.5 restaurant offline and bidirectional sync

Status: **IN PROGRESS**.

Restaurant & Cafe is not accepted. This pass recorded the real feature set, kept the 30-day sale rule, and fixed the two API tests that had gone stale because their sale date was 2026-10-19. It did not add a second sync queue, a second inventory ledger, or a production key. Nothing was deployed. No protected database was opened.

## What already works

- A register stores dine-in, takeaway, and delivery tickets in SQLite `table_sessions` and `table_session_items`.
- Menu modifiers refresh into `menu_cache` and stay readable when the menu request fails.
- When the order API is unreachable, the register queues an `open_order` event on the existing sync queue. The server merges lines by id.
- Cash sales stay on the sale sync path. Card, QR, and pay-later are not marked paid offline.
- A second dine-in upload for a table that already has an open order is rejected. The local ticket is not deleted and the two bills are not merged.
- Catalogue download still uses the existing bootstrap cursor. Upload and download of sales are separate from that cursor.

## What this pass changed

`tests/test_approvals_manager.py` no longer pushes the fixed date 2026-10-19. Those sales are stamped 08:00 UTC on the previous day, which stays inside the 30-day window. The dashboard is read on that same business day at 15:00 UTC, so the UTC+4 hour bucket is still 12:00.

A new test pushes a sale dated 31 days ago and expects `422` with "older than 30 days". A sale from the previous day is accepted. The rule in `sale_service` was not changed.

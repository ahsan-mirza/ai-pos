## What returned 403

`GET /api/v1/orders` is behind `require_capability(OPEN_ORDERS)`. While Open orders & tabs is off, the router returns 403 `capability_disabled` before it checks the query or the role. That is the O8.7 result. The Downtown user was signed in. The disposable business had not turned the module on.

The same user is stored with a branch. `PUT /api/v1/settings/profile` then returns 403 `forbidden`: only a business-wide administrator, a user with no store, can change the business type. The store-bound Downtown admin cannot switch the module on. That refusal is the existing rule.

# O8.2 PostgreSQL RLS

Policy revision: **implemented**. Direct SQL execution of this text is in `O8-POSTGRESQL-RLS-FINAL-ACCEPTANCE.md`. That run used disposable `axizpos_o82` on `127.0.0.1:55941` as `ai_pos_app`, then deleted the cluster. No protected database was migrated.

Alembic `20261122_0130` enables and forces row-level security on:

| Table | Predicate |
| --- | --- |
| `bootstrap_snapshot_items` | tenant |
| `bootstrap_setting_snapshots` | tenant |
| `catalog_changes` | tenant |
| `catalog_feed_counters` | tenant |
| `terminal_allocation_consumptions` | tenant |
| `staff_provisioning_events` | tenant |
| `bootstrap_sessions` | tenant, and `store_id` / `device_id` when `app.store_id` or `app.device_id` is set |
| `terminal_allocations` | tenant, and `store_id` / `device_id` when those settings are set |

The predicate is the pharmacy form from `20261119_0119`: the row matches `app.tenant_id`, or `app_owner_may_bypass` is true for the table owner. `app.bypass_rls = on` is not enough for `ai_pos_app`.

When `app.store_id` and `app.device_id` are unset, the extra clauses do not filter. The request session today sets `app.tenant_id` only. Branch and terminal checks in `consume_for_sale` stay in force. Setting the extra GUCs in a test tightens the policy without blocking a normal request.

`catalog_changes` has no store column. A branch predicate was not invented for it.

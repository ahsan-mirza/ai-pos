# O8.6 staff and access

Status: **IN PROGRESS**. The save failure is identified and corrected in source. The running acceptance executable does not contain the correction, so the native click has not been repeated.

## What failed on the O8.5 window

The Staff & Access form was filled and Create staff was clicked. The notice was "Staff could not be created." `cached_users` gained no row and `staff_provisioning` gained no event.

The command never started. `createRegisterStaff` sent `full_name` and `role_name`. Tauri 2 command arguments are camelCase, matching the other desktop commands (`storeId`, `batchId`). The invoke was rejected before `create_local` ran, and the older UI replaced that string with the generic sentence.

## Correction

`apps/desktop/src/lib/tauri.ts` now sends `fullName`, `roleName`, and `userId` for create, edit, PIN reset, and disable.

A new person id is a UUID. The server parses `user_id` with `uuid.UUID`. The previous `staff-<nanoseconds>` id could not be stored even after a local save.

A blank name or username is refused before a row is written. The PIN rule is unchanged: four digits, stored only as an Argon2 verifier.

The panel already keeps a non-empty string from the command. A local save that the server has not accepted stays pending on this register. A missing token, a refused session, a permission denial, and a network failure still use the existing outbox statuses. Those events stay out of `sync_queue`.

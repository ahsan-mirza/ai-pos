# O8.2 allocation on the live sale path

Status: **PASSED WITH LIMITATIONS**.

An offline sale of a stocked product now draws the verified SQLite grant and writes the queue row in one transaction. The queued payload carries `allocation_id`, `product_id`, `quantity`, and the sequence that commit assigned. An overdraw writes neither the decrement nor the queue row.

## Path

Offline product selection calls `terminal_allocation_balances`. `allocation::verified_balances` returns only grants whose signature and device binding still verify. `withTerminalAllocation` stamps `allocation_remaining` onto the product. Online selection does not stamp it.

The product card keeps branch on-hand and adds the register remainder. The variant grid uses the stamped remainder when the field is present. Search, barcode, weighed PLU, grocery suggestions, and the bag fee go through `stamp` before they enter the cart. `cart.ts` `stockError` refuses a missing or short remainder and does not use `stock_quantity` for that decision.

`enqueue_events` calls `allocation::commit_queued` when the session mode is `offline`. That function sums stocked line quantities from the local product row, ignores services, open-price lines, recipes, and serialized rows, and consumes the verified grants. `Db::enqueue_consuming` updates `terminal_allocations` and inserts `sync_queue` in one SQLite transaction, then stores the sequences on the sale payload. A shortfall returns an error and leaves both tables unchanged.

An online session still calls `Db::enqueue` without a local draw. The server sells only `inventory_levels.available`, which already excludes `quantity_reserved`.
